# Passport Auth — FIDO8TOTP

面向 FoloToy AI Passport 的离线认证器应用，提供本地 OTP 验证码、按需开启的 Wi-Fi 账号管理，以及实验性的 BLE FIDO。本分支使用独立应用界面，不复用上游硬件测试菜单。

**硬件与工具链：**ESP32-C3、8 MB Flash、无 PSRAM、240 × 320 屏幕、三个按键、ESP-IDF **5.5.6**。平台说明见[上游文档](docs/README.zh_CN.md)，开发约束见 [AGENTS](AGENTS.zh_CN.md)。

## 开始使用

1. 新设备的默认解锁顺序为 **UP、UP、DOWN、DOWN、OK**。请在 **Settings → Security → Change PIN** 修改这个公开默认值；兼容升级会保留原有 PIN。已完成的错误提交现在保存到 NVS，非深睡重启和断电不会清零；成功解锁或自动擦除实际完成后清零。仅在计数变化时写入，不按单次按键写入。原有第 5 次锁定、**超过 8 次自动擦除**策略在启用后会跨重启累计，请勿拿真实令牌大量试错。旧固件已经丢失的错误记录无法补回。
2. 令牌主页短按 **OK** 进入设置，**UP/DOWN** 选择菜单，长按 **OK** 通常返回；在令牌主页长按 **OK** 锁定。在 **Display & Audio → OTP View** 中可循环选择 **Card / List 3 / List 4**，列表为每屏纵向 3 或 4 个账号，并非横向窄网格；列表模式下 UP/DOWN 直接翻页、首尾循环，卡片模式仍逐个切换账号。每个列表项目使用圆角矩形边框，不再对首项做选择高亮，因为这是按页浏览而非逐项选择。设置复用五行菜单面板：分组标题、当前组最多三项、位置提示；UP/DOWN 仍可跨组访问全部 15 个逻辑选项，不再常驻整套长列表控件。视图偏好与账号数据分开保存，长名称裁切，不换行挤掉验证码。未校时提示放在内容区、底栏上方，各视图始终保留 **OK:Set** 入口说明。
3. 打开 **Settings → Network → Wi-Fi Hotspot**。独立页面显示完整 SSID 和 8 位密码；UP/DOWN 只在热点开关与 Back 之间选择，OK 执行，长按 OK 返回而不改变热点状态。连接页面显示的热点后打开 `http://192.168.4.1/`。
4. 网页管理账号、修改设置时，设备必须保持本机解锁。使用验证码前请校准时间，尤其是在完全断电后。
5. 管理完成后关闭热点。本应用为控制内部 RAM 使用，故意让 Wi-Fi 与 BLE 互斥运行。

### 每台设备独立的热点

固件读取出厂芯片 MAC，作为 12 位十六进制设备标识。**不烧写任何 OTP/eFuse 位。**热点名称为：

`Passport-<设备标识后六位>`，不再附加密码尾串。

热点使用 8 位大写十六进制 WPA2 密码，通过公开域标签 `Passport-Auth WiFi v1` 与芯片标识做 HMAC-SHA1 派生。密码不再是所有设备共享的硬编码值，清空令牌也不会改变它。但它仍然**可以由公开芯片标识推算**，并非高强度访问控制。8 位是 WPA2 的最低长度，偏重连接便利性；SSID 不再暴露任何密码字符。本版不增加二维码画布或解码器，Wi-Fi 页复用 Lab 菜单控件，开关、SSID、密码、网页地址和 Back 使用相同字号及 30 px 行距。请只用于近距离、可信设备管理。网页 API 显示设备标识和 SSID，不返回热点密码或已保存的 OTP 密钥。

## OTP 账号

设备最多保存 **16 个账号**，每个账号独立设置算法、位数与周期。

| 类型 | 验证码 | 周期 | 密钥输入 |
| --- | --- | --- | --- |
| TOTP / HMAC-SHA1 | 6 或 8 位数字 | 1–255 秒，通常 30 秒 | Base32 或标准 `otpauth://totp/` URI |
| TOTP / HMAC-SHA256 | 6 或 8 位数字 | 1–255 秒 | Base32 或 URI |
| TOTP / HMAC-SHA512 | 6 或 8 位数字 | 1–255 秒 | Base32 或 URI |
| Steam Guard | 5 个字符 | 固定 30 秒 | Base32，或在网页本地转换已有的 Base64 `shared_secret` |

网页支持新增、编辑、搜索、删除与导入。编辑时密钥留空表示保留原密钥。URI 导入支持 `algorithm`、`digits`、`period`、`issuer` 和 `encoder=steam`。导入会先校验全部输入，再逐条保存；中途出错会说明已保存数量。目前不支持 HOTP、Google 迁移二维码载荷，也不负责从其他应用提取 Steam 密钥。无需提供 Steam 密码、登录 cookie 或 `identity_secret`。

设备端数字验证码按 **3 + 3** 或 **4 + 4** 分组显示，Steam 显示五个字符。没有账号时显示明确空状态，不显示页码或倒计时。设备内置字体主要覆盖拉丁字符，非拉丁账号名称需要另外验证字形覆盖和实机显示。

### 时间

TOTP 使用 UTC 秒级时间戳，时区和 12/24 小时制只影响显示。手动时间设置包含**秒**：**UP/DOWN** 调整当前字段，**OK** 切换字段，长按 **OK** 保存，长按 **UP/DOWN** 取消。网页可同步浏览器时间并显示近似时间偏差。设备使用 ESP-IDF 的 RTC＋高分辨率系统时钟；深睡唤醒保留已校准时间，冷启动或非深睡重启后需要重新校时。在此之前显示 `SYNC TIME`，不生成验证码。校时本身不写入 NVS。

启动时 USB 已连接、应用日志控制台已开启时，现有 tick 任务会输出最多六组 `CLOCK_COMPARE` / `MEMORY` 样本，随后停止这段启动采样，不新增监控任务，也不在设备上保存历史。`hrt_us`、`rtc_us` 是同一起点的累计微秒，`diff_us` 为 RTC 减去 HRT。相对漂移为 `diff_us / hrt_us × 1,000,000` ppm，折算累计误差为 `ppm × 0.0864 × 天数` 秒。清醒样本不能证明深睡精度，温度变化和长期外推仍需单独实测；SDK 的高分辨率时钟指标也不是本板已测得的绝对 UTC 精度。

### 快速 RC 睡眠补偿：已实现不等于已硬件验收

新的默认构建选择 C3 的 **RC_FAST/256**：`CONFIG_RTC_CLK_SRC_INT_8MD256=y`、启动校准 3000 周期、`CONFIG_AUTH_RTC_MAINTENANCE=y`。已有根目录 `sdkconfig` 不一定跟随新 defaults，须核对实际生成配置，或使用隔离固件门禁。8M 是沿用的配置名。独立路径通过实际所选 RTC MUX 每次重新测量 3000 周期，并检查测量前后源一致；这不改变 SDK 另一处短周期睡前校准。慢／快源使用独立、有版本／CRC 的模型及系数键，不改账号数据。

48 位／Q19 账本分别保留原始桥接量、修正量、UTC 小数相位及比例除法余量。**正 ppm 表示走快：**`修正量 = 原始量 × 1000000 / (1000000 + ppm)`。新源从 **0 ppm** 开始，不把旧偏快观测或温度预测写成固定补偿；每个活动段冻结系数。唤醒只替换一次绝对 UTC 并消费该段，已知清醒 HRT 单独计入；取消／拒睡只撤销新暂存锚点。设时返回失败可重试；返回成功但时序不可信则消费为不确定状态，禁止重复替换并要求重校时。PIN 单调计时与凭据格式不变。

请用**已准确设置系统时间的手机，在 Wi-Fi 网页显式点击同步**提供学习参考，状态轮询不会自动同步或学习。四条目一次性 HRT 探针、浏览器 UTC／单调时间配对、2 秒 RTT、1 ms 设备窗口及 5 秒总年龄限制共同准入；声明的手机／量化误差界为 1 秒，不是固件测得的手机精度。手动设时、旧命令和质量无效的同步仍可校时，但不训练。学习从独立参考经过量中扣除已知清醒 HRT，与**未经补偿**的桥接历史比较，不从已补偿墙钟偏差反推。须有两组一致、不重叠的合格观测，每组原始桥接暴露至少六小时、观察区间不超过 30 天、参考／计时不确定度不超过暴露量的 100 ppm。证据不足保持原系数；±20000 ppm 是软件拒绝范围，不是芯片公差或精度承诺。

合格且显著变化的系数单独保存，不在同步操作或维护启动中写 NVS；包括无记录时首次保存，都须冷启动或上次尝试后达到 24 小时内部预算，失败也消耗额度。冷启动重新完整等待，未保存的学习证据会丢失；异常／不支持的已有记录不覆盖。温度模型仍按固定 12 点、三个分箱、3 °C 跨度及 RMS ≤100 ppm 学习，但不再叠加 UTC 速率修正，其独立模型保存规则与系数预算区分。采样仍在已有应用任务、LVGL 锁外运行，深睡前完全卸载传感器。

有可信接续的休眠中，每隔 **900 秒通过正常 SDK 定时启动**恢复一段、重新直接测频，然后在 BSP／屏幕／音频／无线初始化之前再次深睡；不采温度、不提交 NVS、不新增常驻任务。只有纯 timer 唤醒可走此路，混合唤醒源、安装失败、状态无效、已观察按键及拒睡均转完整启动。GPIO0 早期数字观察器粘性记录下降沿、硬件待处理状态和按住低电平，原有守卫隔离整次唤醒手势后才接受正常输入。旧校准／重睡 wake-stub 仍**关闭**（`CONFIG_AUTH_RTC_WAKE_STUB`），不是本路径。

观察器之前的 ROM／SDK 启动及最后 SDK／CRC 尾部仍有未经证明的短脉冲盲区。最短有效按键、反复睡醒、启动稳定性、整板电流和长期 UTC 精度须实机验收；构建通过不意味着 20 ms 唤醒、某个微安上限或每日 1–2 秒。没有增加前后 TOTP 时间窗口。硬件掉电仍是冷启动，需要重新校时。`RTC_CAL` 是诊断，不是绝对时间参考；`pre_tail_gap_upper_us` 不是端到端盲区实测。详见[设计与验收计划](docs/assets/rtc-calibration-design.zh_CN.md)。

### 无需串口的只读时钟证据

`GET /api/status` 保留原字段，新增 `time_set`、`time_us`、`time_sample_hrt_us`、`time_sample_window_us`、`time_sample_valid` 和 `rtc` 对象。只有 `time_sample_valid` 为真时才使用微秒时间；读取失败、未校时或采样窗口超过 1 ms 时无效。HRT 值是采样窗口中点，不是独立 UTC 基准；与外部时钟比较时仍须考虑网络往返不确定度。

`time_probe` 提供一次性 ID、配对 HRT、窗口及独立于 UTC 的 HRT 有效标记，只用于浏览器显式同步。`rtc.policy` 为 `selected_source_ratio`，C3 上 `source=2` 表示 RC_FAST/256。`ppm` 与 `ppm_qualified` 描述活动比例；本影子增量中，没有已保存合格值的源保持零／未合格，不因候选就绪而自动启用。`reconciled_elapsed_us` 是最近一段未经补偿的桥接量，包含关机和早期启动，不是纯物理深睡；`corrected_elapsed_us` 为该次实际应用的修正推进量。`raw_chain_us`、`corrected_chain_us`、`awake_total_us`、`maintenance_count` 暴露保留结算，`learning_reason`、`reference_status` 区分拒绝、证据不足和设时不确定。`sdk_correction_us` 仍是配对相位的“修正目标减去 SDK”有符号差，仅在 `sdk_sample_valid` 为真时有意义，**不是相对于真实 UTC 的实测误差**。温度模型合格只说明分析资格，并非已应用；显式校时成功会清除历史接续快照。

这个 GET 不校时、不复位、不采集温度传感器、不写 NVS。应用任务将时钟状态复制到原有有界快照，HTTP 不直接读取可变模型。测量时保持供电及无线条件一致：开启热点会改变热状态。保留时钟实验期间不要打开串口；串口导致的复位会使该会话失效。仅分享时钟／时间字段，不要分享完整响应，其中还包含原有热点会话令牌。

### 有界校准历史与影子自适应

应用最多保留 **100 条有效、独立的外部参考窗口**，不是 100 次同步点击或内部测频样本。频偏由带小数的原始桥接量和“参考经过量减清醒 HRT”重新计算，不平均秒数偏差。准确的清醒重复参考会保留待确认学习，报告结果 **13**（无新睡眠）。

本增量**仅影子运行**：原双窗口发布器与新估计器都不能改变活动系数；兼容的已有合格保存值（包括当前 -870 ppm）继续使用。加权中位数筛查、暴露／时间新鲜度／参考质量权重，以及按时间留出验证，只产生诊断候选，不自动启用。`READY` 或留出改善都不能证明离线 30 天正负 3 秒的目标。温度与电池电压是带年龄的清醒端点观测，不是睡眠均值，也未启用环境补偿；CW2017 电压不等于 VBUS 测量。

两个 RTC 待存行区分已接受与已持久化证据；队满不覆盖旧行，之后的准入窗口推进基线并明确累计丢弃数。历史采用独立六小时尝试预算，失败也消耗额度，冷启动重新等待。允许的清单事务会检查点保存已接受／丢弃计数；冷掉电仍可能丢失更新的待存行／计数，连续性会标为不完整。静默维护不加载、估计、导出或写入历史；历史不可用／损坏不替换现用补偿，也不擦安全存储。

解锁后使用网页的 RTC 历史查看／刷新与 JSON 导出。经认证的 `GET /api/rtc-history` 每页至多五条，`generation` 与 64 位测量值使用十进制字符串。后续请求为 `?generation=<返回代际>&cursor=<next_cursor>`；代际改变返回 **409**，须重新遍历。导出限制为 20 页／100 行，出错会中止而不是下载残缺数据。历史摘要放在新端点，原 `/api/status` 保持兼容。导出白名单不含账号、设备身份、热点／探针令牌、参考身份或内部 epoch。HTTP 使用有界邮箱，只有原应用任务复制可变历史。

本分支使用自定义 8 MiB 分区表：

| 分区 | 偏移 | 大小 |
| --- | ---: | ---: |
| `nvs` | `0x9000` | `0x6000` |
| `phy_init` | `0xF000` | `0x1000` |
| `factory` | `0x10000` | `0x7E0000` |
| `rtc_hist` | `0x7F0000` | `0x10000` |

历史只使用 `rtc_hist`，账号／PIN 存储及应用起点不移动。设备旧分区表没有此分区，仅刷应用不能开启持久历史，会退回只使用原系数；之后需要**另行批准分区表与应用更新**，用验证过的分段镜像保留原 NVS／PHY／bootloader。本改动不自动擦除、不用合并镜像覆盖用户数据、不操作 eFuse。原生测试使用真实 IDF 5.5.6 NVS 引擎，板上断电、堆／栈余量及长期 UTC 精度仍需独立验收。详见[实施与验证记录](docs/assets/rtc-calibration-design.zh_CN.md)。

### 启动阶段实测

2026-11-09，验证包 `bb33c1f2a107`（ELF `8201249e03a2`）以仅刷应用区的方式写入，保留匹配的分区表及 NVS。在 USB 供电、BLE 关闭时，HRT 计时 31.476992 秒，内部 RC RTC 计时 31.428623 秒；RTC 落后 48.369 毫秒，该区间平均相对偏差为 −1536.65 ppm。六个启动累计区间的平均值由 −801.41 变化到 −1536.65 ppm，尚未达到热稳定，也不是深睡测量。仅假设最后这段短测系数保持不变，会得到相对落后 132.77 秒/天；这只是换算，不是实测日差保证。本次没有使用绝对 UTC 基准或整板测流仪器。

原生启动采样中，空闲堆稳定为 124,380 字节，最大内部连续块 94,208 字节，最低空闲堆 119,940 字节，tick 任务栈最低余量 1,984 字节。32 KiB LVGL 池初始空闲 3,156 字节、最大空闲块 1,960 字节。另一个 64 位主机上的真实 LVGL 测试使用 64 KiB 池，完成 10,000 次刷新而未观察到存活分配增长；它不能代替原生设备长期 UI、射频切换和休眠验收。

## 状态与安全

- 顶栏留出圆角安全边距，去掉 F8T 字样。非锁屏页面显示 HH:MM，12 小时制在后面显示 AM/PM；锁屏保留原有大时钟，不在顶栏重复。
- 蓝牙图标：灰色表示不可用或关闭，琥珀色表示已启用但未连接，绿色表示已连接；Wi-Fi 图标表示热点状态。
- 电量未知或 0–10% 时为红色，11–30% 为橙黄色，优先于其他颜色；高于 30% 后，未连接 USB 为灰色、连接 USB 为绿色，连接 USB、启用 80% 保护提醒且达到阈值时为蓝色。**`*`** 仅在 USB 已连接且提醒开关开启时显示；拔掉 USB 会隐藏它，但不会关闭已保存的提醒设置。**`+`** 是 USB 提示。USB 连接不是充电电流测量，80% 功能也只是提醒，不是硬件断充。电量 SOC 的 I²C 查询缓存五秒，USB 状态变化立即重新查询，验证码倒计时维持原刷新频率；这不是已测得的电流下降。
- **Wipe All Tokens** 和 **Reset FIDO** 均需确认，移动选择或返回即可取消。网页清空请求只在设备上打开确认，不会直接擦除。
- 清空全部令牌会删除 OTP 账号及 FIDO 凭据/PIN 状态；Reset FIDO 只针对 FIDO。删除不能撤销，请在其他安全位置保留各服务恢复码。
- 默认启用多次错误设备 PIN 后自动擦除。锁定/自动擦除规则与实验性 FIDO client PIN 分开。
- 网页修改操作要求本机解锁和当前热点会话令牌，不开放通配 CORS；只有应用任务回报完成，界面才显示已保存。HTTP 任务使用有界、不含密钥的数据快照，不直接读取正在修改的账号结构。
- NVS 出错不再自动全擦芯片。无法识别或损坏的账号存储会明确失败，而非静默覆盖原账号。

## 音频电源三态

- **ON：**播放前恢复 codec 和 I2S，再写入 PCM。
- **STANDBY：**Audio Beep 已开启但空闲，保留 codec 对象、配置及已启用的偏置，
  静音并停止 I2S；由现有应用 tick 处理空闲截止，不新增音频监控任务。
- **OFF：**关闭 Audio Beep 或进入深睡时使用 BSP 软件关断路径，不走保偏置待机。

本板 ES8311 与常通功放没有 MCU 可控的供电开关，软件 Off 不等于物理切断 VDD。
切换杂音、待机电流和整板睡眠电流仍需实机及仪器验证。

## Lab / Experiments

**BLE FIDO 默认关闭。**设备 Lab 提供 BLE 传输开关、USB 应用日志开关，以及 FIDO 站点列表、删除和重置。

远程 CTAP Reset 返回 `CTAP2_ERR_NOT_ALLOWED`，请从设备 Lab 确认重置；不会在确认前先清除 PIN，也不会把它误转成 OTP 清空请求。

当前 FIDO 凭据模型仍是实验实现，未经认证，也尚不能当成生产级多账号 passkey 实现。手机注册/登录仍需端到端验收，主机测试通过或 CBOR 格式合法并不能证明浏览器兼容。

ESP32-C3 的 USB Serial/JTAG 是固定功能，**不能直接枚举成可编程 USB HID FIDO2**。USB Log Console 只控制应用日志，不关闭硬件 JTAG。本固件不烧写 eFuse，也不配置不可逆的安全启动或 Flash 加密。NVS 不是安全芯片，不应将当前开发固件等同于加固的商用安全密钥。

## 内存与验收

OTP 运算使用固定大小缓冲区，不申请堆内存。热点固定 HT20（20 MHz）和 11 dBm 发射功率上限，包含 PHY 启动上限；这只是配置，不是整板电流实测值。不会为降低内存数字而盲目缩小 BLE 缓冲、任务栈或关闭看门狗、栈保护。规格书的 5 μA 深睡数值针对芯片，LCD、codec、常通功放、稳压和充电电路使整板电流必须单独测量。

Wi-Fi 请求和响应均有上限，停止或启动失败时释放 HTTP、DNS、socket、netif 和驱动资源；只有当前射频停止完成后才能启动另一种传输。ESP-IDF 默认事件循环属于共享服务，首次创建后可能常驻，这是设计保留而非逐次泄漏。

维护的 `tests/auth_ui_host` 回归会真正执行 LVGL 绘制：预热后固定保留 15,728 字节，
连续三轮绘制 List 4 及全部 15 个设置项，并保留断言。其 64 KiB 主机池用于适配
64 位指针，不能当作设备 32 KiB 池在 BLE 或 Wi-Fi 开启时已经通过交互验收；
这些原生设备组合仍需单独测试。

这些约束和主机测试通过都**不等于终身无泄漏保证**。仍需在实机长期测试中记录空闲堆、最大连续块、历史最低堆、任务栈余量和复位原因，并反复修改设置、开关热点、启停 BLE。构建、主机测试、设备测试和未验证项必须分别报告；刷入或正常启动不能证明无泄漏，也不能证明 FIDO 注册成功。
