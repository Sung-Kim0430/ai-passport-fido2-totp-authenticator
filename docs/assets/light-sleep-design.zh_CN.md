# 自动浅睡眠

## 已批准行为

用户于 2026-11-17 批准自动浅睡眠方案。保留现有空闲深睡眠策略，启用 Tickless
Idle，让 ESP-IDF 选择短暂的空闲时间；应用不主动暂停任务，也不改变 ADC 按键引脚用途。
保留 40–160 MHz CPU 范围。背光 PWM 使用 RC_FAST，在浅睡眠期间继续运行。
将 LVGL tick 周期从 2 ms 调整为 5 ms，避免它阻止所有空闲睡眠机会；按键采样周期不变。
SDK 的外设和无线电电源锁继续决定是否允许睡眠。配置已启用不代表设备实际进入睡眠或已省电。
启用 `CONFIG_USJ_NO_AUTO_LS_ON_CONNECTION`，让 USB 连接持有禁止浅睡眠锁；
拔线后仍允许自动浅睡眠。

另一种显式熄屏睡眠需要可恢复的 ADC/GPIO 交接和应用任务协调。
已批准的自动方案利用现有 SDK 调度，并保留按键轮询。

## 时钟记账

浅睡眠期间，SDK 根据 RTC 重建高精度计时器时间。
这部分经过量不得计入现有的独立清醒时间坐标。利用固定版本 ESP-IDF 5.5.6 的睡眠上下文，
取得 SDK 替换的准确 RTC 区间、睡眠结果和 SDK 校准周期。
仅成功区间进入有界 RAM 累计器；拒绝的请求不推进累计器。
使用最近一次独立直接测量的周期转换各区间，跨区间保留小数微秒，单独记录 SDK 的整数贡献。
周期变化只影响后续区间。
还需要记录 SDK 在每次成功浅睡眠前后对 libc RTC/HRT 偏移的调整：
`esp_set_time_from_rtc()` 会在唤醒时替换 `s_microseconds_offset`。
固定版本的适配器在临界区读取这一私有标量；空闲回调不调用墙钟函数，也不获取 libc 锁。

睡眠回调仅收集数值：不分配、不阻塞、不记录日志、不操作 LVGL、不修改墙钟，
也不写 NVS、不测温或校准。应用任务在处理事件、应用校时参考和准备深睡眠之前，
读取一致的累计快照。从清醒坐标中减去 SDK 贡献，向现有账本加入原始及修正后的睡眠经过量，
且仅应用一次“修正量减 SDK 贡献，再减 SDK libc 偏移改变量”的 UTC 差额。
PIN 和协议的单调截止时间继续使用现有 SDK 时钟，保留已有 RTC/NVS 结构。

若延迟校时参考的时间戳早于最近一次已处理的睡眠退出时间，仍可设置 UTC，
但不得使用存在歧义的坐标训练系数。学习窗口计入保守的 RTC 边界不确定度；
窗口被拒绝时保留最近的合格系数。溢出、时钟源改变、校准不可用或采样失败时，
阻止后续自动浅睡眠；UTC 修正失败时请求重新同步，不继续宣称时间可信。
不修改 SDK 源码或受管理组件。私有睡眠上下文 API 隔离于平台适配层，升级 ESP-IDF 时必须复核。

## 边界与验证

应用策略和纯算术放在 `main`，可复用背光和 LVGL 配置放在 BSP。
不新增菜单、常驻工作任务、持久化设置、分区、无线电服务或自动 Flash 写入。

主机回归覆盖睡眠成功与拒绝、小数累计、计数回绕、非法周期、溢出、重复处理、
UTC 正负修正、过期参考、失败处理，以及浅睡眠转深睡眠的接续。
除纯算术外，也用 SDK 桩运行实际平台回调适配器。
在 ESP-IDF 5.5.6 环境运行仓库完整验证并核验归档，分别报告构建、主机测试和设备测试。

另行批准刷入后，检查三个按键、长按、不同亮度下的背光、TOTP 时间、深睡唤醒、
无线电和音频活动及睡眠计数。连接 USB 主机会阻止自动浅睡眠，
无线电也可能阻止睡眠；还应测试合适的拔线空闲区间。
省电量和 RTC 精度需要仪器及外部时间参考实测，在测量前保持未验证状态。
