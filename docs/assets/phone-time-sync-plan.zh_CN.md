# 手机时间同步实施计划

> **供执行代理使用：** 使用 executing-plans 流程，并进行独立计划与最终代码审查。保留当前工作区；未取得相应用户授权时，不提交、推送或刷入本次增量。

**目标：** 通过毫秒时间戳、多轮延迟测量及最终一次时间设置，改善手机主动校时。

**架构：** 轻量鉴权采样接口记录设备接收和发送时的单调时间戳。浏览器采集有界批次，扣除设备处理耗时，从延迟较低且一致的样本估计 UTC 与设备时间差。现有应用所有者将选中的参考时间推进到实际执行时刻。

**技术栈：** ESP-IDF 5.5.6 C、浏览器 JavaScript、主机 C/Python/Node 测试。

## 已确认设计及边界

用户已确认毫秒时间戳、8～16 轮测量、扣除设备处理耗时、低延迟筛选及最终一次校时。实施时采用 12 轮顺序采样，采样预算三秒，至少六个有效样本。选择最快的三分之一（至少三个、最多五个），取 UTC 减设备时间差的中位数；所选组任一样本与中位数的绝对偏差超过 20 ms 则拒绝。使用所选组中最新的采样作为参考锚点。逐样本及整个批次比较系统时间和单调时间的增量；发生时间跳变时拒绝，避免进入校准。

四个时间戳包围 HTTP handler 与浏览器请求，并非物理无线收发时刻。扣除 handler 耗时后，剩余仍包含传输、调度、序列化及浏览器开销。假设上下行对称时，用剩余往返的一半估计单程延迟；不对称仍属于不确定度。

将手机 UTC 不确定度（假设界限一秒）与传输、量化、样本离散度分别记录。不能因为传输较快就降低手机误差界限。界面分别展示传输不确定度及手机限制。整个批次只产生一次参考事件，历史估算仍保持影子模式。

使用独立的 16 项一次性采样缓存，与旧状态轮询隔离。采样要求当前会话和已解锁快照；保留 POST 鉴权及所有者解锁检查。参考五秒过期，无效版本 2 请求必须失败，不降级为整数秒。旧网页保留原有协议。采样期间持有现有 busy 状态、暂停轮询和其他修改，拒绝设备或会话变化，并在所有退出路径恢复控件。没有合格样本则不提交校时。

## 任务

### 协议与数值约定

`GET /api/time-probe` 使用 `X-Passport-Session`，返回 `{version:2,id,received_us,sent_us,valid}`。设备时间戳以微秒表示，为非负 JS 安全整数；handler 耗时不超过 500,000 us。版本 2 POST 在 `SYNC_TIME` 及旧 `value` 上增加 `reference_version:2`、`reference_probe_id`、`reference_utc_us`、`reference_rtt_us`（1..500,000）和 `reference_spread_us`（0..20,000）。字段均为整数，UTC 限制为 2020..2100。设备重新计算 `network = rtt - (sent - received)`，结果为负则拒绝。缓存锚点为 `received + floor((sent-received)/2)`，浏览器通过所选组偏移中位数将该锚点映射到 UTC。传输不确定度为 `ceil(network/2) + 1000 + spread`；传给现有学习接口时再加独立的 1,000,000 us 手机界限。例如 RTT 30,001 us、handler 20,000 us、离散度 200 us，对应传输不确定度 6,201 us。

每轮使用不超过批次剩余三秒预算的 500 ms 可取消期限，覆盖 fetch 和 JSON 响应体。单轮超时或无效可跳过，会话或锁定变化及系统时间跳变则终止批次。请求采用 AbortController 加 Promise race，保证响应体挂起时也能释放 busy。最终 POST 不自动重试，包括结果不明确的网络失败及结果超时。版本 2 所有者参考设置 `max_age_us=5000000`，紧邻实际设置系统时间前再次检查；旧参考保留原有语义。

## 补充固件审查

此次补充审查覆盖应用启动与休眠回收、RTC 续时和浅睡眠记账、HTTP／手机校时、文本／CBOR 解析、BLE 凭据材料与账号存储，发现并修复：

- 文本命令缺少参数、参数非法、负数、溢出或多余参数时，可能被当作有效修改操作，包括误删第 0 个 OTP 账号。
- 删除按键驱动可能与共享定时器正在执行的回调冲突。现在先停止组件定时器，再等待同一个串行定时任务上的一次性屏障；超时则保留资源并取消休眠交接。启动时也先检查按键初始化结果，再开放输入。
- BLE 密钥、用户句柄和计数器的持久化错误可能被忽略。现在读取和写入稳定密钥都确认提交；错误时保留既有材料，认证不会创建缺失的站点盐；这些路径不再回退到临时计数器或在材料不可用时返回成功。
- 凭据允许列表原先只保留最后一条。BLE 现在持有整个列表的有界副本，并在确认后逐条匹配。
- 原先可接受不完整／带尾随内容的 CBOR、被截断的站点标识及超出响应缓冲区能力的长度。现在明确拒绝；仅用于显示的名称仍可在 UTF-8 字符边界缩短，与身份标识的严格检查分开。
- 三项主机测试依赖本机临时目录环境变量；现在未设置时回退到系统临时目录。

后续的[完整 RP 存储修复](fido-rp-storage-plan.zh_CN.md)替换了有效站点记录使用的旧版 12 字符命名空间。按需迁移保留旧盐，独立保存用户句柄和删除状态，每次使用摘要键时都检查完整 RP 标识，并通过删除标记防止旧凭据恢复。无法确定完整身份的旧记录保持只读。此前被覆盖的用户句柄无法恢复，旧固件也无法遵守新删除标记。实验性 BLE 模型仍待真实浏览器及设备验收。
