# RTC 混合校准设计与实施计划

> **代理执行要求：**使用 `subagent-driven-development` 或 `executing-plans` 逐项实施，任务之间执行测试和评审。未经授权不得提交或烧录。

**目标：**结合本机温度学习与周期性 RTC 安全频率测量，提高认证器睡眠计时精度，同时不丢失用户唤醒、不改变安全倒计时。

**架构：**保留 SDK RTC/HRT 计时。独立维护保留小数余量的分段睡眠时间账本，正常唤醒时仅校正一次 UTC。在现有应用任务采集温度及模型观测；定时维护唤醒只运行经过审计的 RTC/ROM 代码。

**技术栈：**ESP32-C3、ESP-IDF 5.5.6、C11 主机测试、IDF 温度传感器、RTC 快速内存、GPIO0 按键唤醒、现有 NVS 与应用事件循环。

本文不授权应用／设计提交、push、eFuse 编程、Flash 擦除、增加接线或新固件烧录。之前的烧录批准仅对应当时准确镜像。SDK 保持在工程外，不改 managed components。

## 已核实约束

- C3 慢 RC 约 136 kHz。1024 周期测量本身约 7.53 ms，尚未包含其他操作；总计 2–3 ms、平均增加低于 0.15 微安均是未验证说法。
- `rtc_clk_cal()` 和普通温度驱动不是 C3 现成的 wake-stub 安全 API。普通 IRAM 不等于保留的 RTC 快速内存。
- SDK 普通深睡入口会安装新的 10 周期校准值；在入睡前安装长周期测量结果不能避免该覆盖。
- SDK 普通运行期变更校准值前会结算累计时间。禁止从 stub 直接写全局因子，绕过这些分段边界。
- stub 原始唤醒位与应用唤醒位编码不同。只有严格的纯定时维护原因可以重睡。
- 外部 32 kHz 不是纯软件选项：其 GPIO0/1 已用于按键／LCD CS。初期保留内部慢 RC；RC_FAST/256 是需单独实测功耗／精度后选择的替代方案。
- 根目录增量 `sdkconfig` 与 `build/project_description.json` 可能陈旧。依据门禁从 defaults 生成的准确配置和归档 ELF 判断交付固件，不能使用旧文件推断。

参考为固定 SDK 的 `docs/en/api-guides/deep-sleep-stub.rst`、`docs/en/api-reference/system/system_time.rst`、`components/esp_hw_support/port/esp32c3/rtc_time.c`、`sleep_wake_stub.c`、`sleep_modes.c` 和 `esp_clk.c`。[官方手册入口](https://docs.espressif.com/projects/esp-idf/zh_CN/latest/esp32c3/)可能描述较新版本，实现以 5.5.6 为准。

## 时钟域与模型

清醒 UTC 保持 SDK HRT。拟合仅在普通任务执行，可使用浮点，stub 不可达这些函数。温度为芯片结温。采用有界统计，至少 12 个有效观测、三个非空温度分箱、至少 3 摄氏度跨度、非奇异拟合，且 RMS 残差不超过 100 ppm。这些只是初始模型准入规则，不是精度保证。只在合格观测温区及传感器配置的 -10 至 80 摄氏度范围内预测。

纯选择模型可针对直接实测锚点 `(T_a, p_a)` 和合格多项式 `M`，在温度不超过 1 秒、锚点不超过 600 秒时计算 `p_pred = p_a + M(T_now) - M(T_a)`。这只是分析候选值，不代表允许用作 UTC 睡眠时基。报告时钟偏快后，应用边界已收紧：每次睡眠准备都执行新的 1024 周期直接测量，即使已有缓存直接周期或合格预测。模型学习与存储预算仍保留，但预测不能替代本次实测。测量失败时，该次睡眠关闭补偿、恢复 SDK 默认 stub，不阻止普通 GPIO-only 深睡；不得取回缓存／模型周期，也不得对新直接周期叠加模型差值。

睡眠期没有新的温度输入，保留已接受周期，直到下次直接测量提交。不声称模型知道期间温度轨迹。成功直接测量仅向后生效；初版不追溯插值过去区间。测试单独覆盖分析预测器，并证明同温度缓存直接周期及合格预测都不能绕过应用睡前新测量。这项风险收敛不能证明已报告误差的根因，也不能消除睡眠期间振荡器变化产生的漂移。

使用现有应用任务，在 LVGL 锁外按截止时间低频维护传感器／模型；不新增常驻任务、无限历史或逐样本 Flash 写入。

## 数值账本与测量提交

C3 原始 RTC 计数器为 48 位，锚点按此掩码保存；求模差值达到 `2^47` 时拒绝。有效 Q19 周期在 `2 * 2^19` 至 `20 * 2^19`（每 tick 微秒的 Q19）之间，含端点。这个宽实现范围不是芯片容差宣称。小数余量小于 `2^19`，会话累计最长 366 天。校验和通过后仍验证这些语义。活动补偿记录异常／损坏时清除补偿 UTC 信任并正常启动，不触碰凭据。

换算使用 `whole = delta >> 19`、`low = delta & ((1 << 19) - 1)`、`tail = low * period + remainder`、`advance_us = whole * period + (tail >> 19)`、`new_remainder = tail & ((1 << 19) - 1)`；发布前检查时长及 UTC 相加，避免直接 `delta * period` 溢出。stub 用到的整数账本辅助函数明确强制内联进 RTC 单元或放进 RTC text，不依赖 `-lm`。

测量完成后先验证周期、采集 ready tick、检查用户唤醒证据，再提交：用旧周期结算至 ready tick，然后原子发布新的未来周期／检查点。取消发生在边界前时，以旧周期结算至新采集的当前 tick，丢弃候选；发生在边界后时保留已提交周期，只结算剩余尾段。每个锚点只推进一次；粘性用户启动请求优先于候选发布。

## UTC 接续与安全计时域

无指针 RTC 会话包含有效性／版本／校验、原始 tick 锚点、累计／小数时间、上次周期、可信绝对 UTC 锚点及粘性唤醒证据。在末端 BSP 交还后、SDK 深睡入口前，最终采集 UTC/HRT／RTC 对应关系。较早的准备阶段可采集模型／周期，但若按键导致放弃睡眠，不能留下活动会话。

正常应用启动、慢 BSP 初始化前，先复制唤醒证据到普通启动所有的状态，以保留检查点副本结算到当前原始 tick `c`。绝对目标为 `UTC_anchor_us + ledger_elapsed_us(c)`，不是当前 SDK UTC 再加睡眠时间。补上采集 `c` 到检查返回的微秒级 `settimeofday()` 之间的 HRT 时间。原始区间覆盖 SDK 关机、维护、bootloader 和早期应用启动；接续后的时间交给普通 HRT。

保留状态为 prepared、active、consumed。成功应用前只操作副本；`settimeofday()` 失败不能标为可信／已应用，也不消费活动检查点。同次启动重试从原检查点重新计算绝对目标。成功后用任务所有的 applied 标志阻止重入，并消费 RTC 会话。若应用成功到消费之间复位，它属于非深睡启动，会失效会话／UTC 信任，因此不能重复校正。活动状态损坏则请求重新校时，不能随意移动相位。

不能由校正 UTC 重置清醒 `esp_timer_get_time()` 截止时间或保留 PIN 的 `esp_rtc_get_time_us()` 锁定，也不能悄悄把它们迁往独立账本。stub 不改 SDK 全局校准／私有时钟状态。测试未结束锁定期间的正／负 UTC 校正、重复维护、失败／重试及冷恢复。硬件冷启动恢复 NVS 凭据／错误次数，但要求 UTC 校时。

## 只读接续证据

接续成功后，缓存 RTC 采样点的完整账本经过量，以及通过 HRT 对齐的可选“独立账本减去 SDK UTC”有符号差值。SDK 样本窗口不超过 1 ms。此项可选诊断失败不得阻止有效独立恢复、消费失败会话或改变恢复目标；只有设时返回及窗口检查成功后才发布诊断成功。显式校时成功会清掉缓存证据。仅新增普通 RAM，不改变保留会话或 NVS 布局。

原有 `GET /api/status` 通过应用任务所有的快照发布这些数值，并提供实时 SDK UTC/HRT 样本、采样窗口和有效标志。HTTP 不读取可变 RTC／模型状态，不执行校准、分配温度句柄、校时或写 NVS。固定响应缓冲为 1024 字节，handler 回归检查全宽整数格式及失败／未校时／慢采样。`reconciled_elapsed_us` 包括关机和启动至采样点的时间；`sdk_correction_us` 不是相对于独立 UTC 基准的误差。比较时须记录无线／供电条件及网络往返不确定度。只分享时钟／时间字段，不分享含原有热点会话令牌的完整响应。

## 模型存储预算

独立版本化 `rtc_cal` 记录保存 schema／版本、慢时钟源、晶振参考、拟合域／准入、有限系数及校验和，不与账号／配置 blob 共用布局。记录不存在则从未标定开始；版本不支持、内容异常或不可读则从未标定开始并禁止自动覆盖，不擦除也不循环重写。

无记录时，首次合格模型允许一次提交。后续自动尝试须至少相隔 24 小时运行经过时间（含睡眠），且有实质变化：预测至少变化 10 ppm，并且残差改善至少 20%，或合格温区扩大至少 2 摄氏度。已有记录的冷启动重新等待保守 24 小时，重复重启不能加快写入。提交失败也要等下个预算窗口，不自动紧密重试。仅成功 NVS commit 后才标记持久化，失败保留上次好模型。显式校时可请求检查点，但不能绕过预算。测试未变化拟合、重复启动、不支持记录、提交失败／中断及尝试次数上界。

## RTC 维护与取消

初始维护间隔为 300 秒，仅为待实测的工程初值。使用有界、晶振参考的测量并显式准备外设；stub 阶段尚未执行 Timer Group 构造函数。审计所有调用、常量、算术辅助函数及可变数据的 RTC/ROM 可访问性。stub 不得调用分配器、日志、NVS、UI、普通温度驱动或 FreeRTOS 锁。

只有会话有效且严格纯定时唤醒才维护。GPIO 证据、组合／未知原因或无效状态进入正常启动。先保存证据，再清除状态；所有等待段和睡眠交接均检查按键，不只检查入口／出口。用户启动请求在会话内单向置位，之后松手或测量完成都不能清除。

超时／失败应有界回退、保留上次有效账本并避免快速唤醒／完整启动循环。记录故障供普通运行期处理；无法证明的底层路径不能仅因编译通过而启用。

最终 CRC／sleep-enable 尾部也属于竞态分析。实验实现会在 CRC 后轮询，成功重睡路径不再写保留数据。8 ms 软件盲区门限包含一个原始计数 tick，并使用每 tick 20 微秒的宽周期上界，不是物理脉宽保证。成功重睡的 `pre_tail_gap_upper_us` 不含最后 CRC，取消返回时可能包含更晚检查点，因此不是全路径峰值。普通边沿锁存及 WFI 后清 SLEEP_EN／返回 ROM 的恢复仍需目标硬件证明。`CONFIG_AUTH_RTC_WAKE_STUB` 默认保持关闭。需实测完整检测间隔和最小覆盖低脉宽，不能承诺任意短脉冲。

## 两组按键

### GPIO0 功能键

UP/DOWN/OK 共用 ADC 分压，数字低电平只能证明唤醒请求，不能识别具体键。保留现有 ADC 转数字输入的睡眠交还与外部上拉电路。

现有守卫在 RELEASE 时撤防，但组件之后仍可发 SINGLE_CLICK。在 BSP 末尾添加一个聚合空闲事件，不改变既有事件取值。自有 BSP timer 上下文在 PRESS_DOWN 设置三键活动手势位，只在组件 CLICK/DOUBLE 尾部之后的 PRESS_END 清掉对应位。仅当全部手势位为空且有效释放态 ADC 持续至少组件配置的消抖区间时通知聚合空闲；ADC 失败或新按下重置稳定释放资格。不使用原组件省电回调：给当前 ADC driver 打开省电会在没有唤醒 ISR 时停掉轮询。

每次启动、包括硬件原因仍为 TIMER 的 stub 用户唤醒，都在初始化按键前武装守卫。按键初始化开始后，只由 button timer 回调修改守卫，移除主任务单次电压采样撤防。聚合空闲前吞掉全部事件，空闲通知本身也吞掉；以后空闲通知不派发应用。仍按住时，超时不撤防。覆盖初始化前已松手且无 RELEASE、长按、抖动、共享 ADC 多键切换，以及旧手势未结束前第二次按下；后者继续隔离到整个分组手势空闲，再接受下一次独立操作。测试真实 BSP 回调与初始化顺序，而非只有纯守卫。

### 独立硬件电源键

产品规格定义其为硬件电源控制：约按住 0.5 秒开机、约 2 秒关机，不是已暴露的 MCU 输入。stub 不能拦截物理掉电。验证安全冷恢复、模型有效性、NVS 持久化及未校时状态，不猜 GPIO，也不承诺断电后仍保留 RTC。

## 有界功耗／稳定性工作

- 保留无线停止所有权、显示保持、共享 I2C 退出，以及音频 ON/STANDBY/OFF。
- C3 温度驱动在安装时取得传感器电源引用，卸载才释放。每个清醒周期复用一个自有句柄，读取间 disable 但不宣称电气关断，深睡前卸载。不逐样本重复分配，不在 stub 启用普通驱动，并验证与共享 ADC 按键共存。
- 检查 `settimeofday()` 返回后才能报告校时成功或重置时钟锚点。
- 记录末端外设停止失败，但不可逆交还后不回到活界面。
- 若实施电池 I2C 降频，独立于倒计时重绘；USB／状态变化及时刷新，收益实测。
- 报告 RTC 占用、堆／最大块，以及应用与 tick 栈余量，保持看门狗和栈保护。
- 不在缺少 BLE 时钟依据时启用自动浅睡，也不只为内存数字改射频缓冲。

### 比例补偿与一次性结算

正 `ppm` 表示未经修正的桥接时间走快。使用 `corrected_us = raw_us * 1000000 / (1000000 + ppm)`，分母为正，软件准入范围为 -20000 至 +20000 ppm；采用检查过的商／余数运算及明确的小数进位。这是拒绝异常的护栏，不是芯片容差。不能先把长微秒时长乘一百万再事后检查溢出。每个活动段冻结系数，更新只影响后续段；原始桥接累计量、修正 UTC 和实测清醒 HRT 独立保存。

每个已武装段只成功替换一次绝对 UTC，消费一次；维护重睡前，从得到的 HRT 驱动 UTC 建立新锚点。不能向 SDK UTC 再加完整经过量、重复乘比例，或用新周期／系数追改过去区间。保留整条维护链的原始／修正累计量及维护次数供诊断。桥接结束与下个锚点配对 HRT，使维护／NVS／测频停留只按清醒 HRT 计一次。不透明 SDK 入睡尾部与 ROM／采样前启动仍属于 RTC 桥接，不能宣称是纯物理睡眠或已扣除未知启动耗时。准备新锚点后若取消／拒睡，进入正常启动前须放弃未实际进入的睡眠段并回滚其暂存统计；设时失败须保留原活动段可重试。

### 浏览器参考与学习准入

复用状态 HTTP 样本作为有界 HRT 探针；即使 UTC 未设置，也提供明确 HRT 有效标记，以及绑定现有热点会话的有界探针标识／缓存。浏览器在请求前后记录 UTC 和单调时间，显式同步时提交探针身份、配对参考 UTC 与不确定度。陈旧、重放、跨会话探针不能学习；设备用 HRT 计算排队年龄，把参考推进至实际执行时刻再设时，并检查返回后才发布参考或系数。缺少质量元数据的旧命令与手动修改照常校时，但不训练。

浏览器系统时间是外部假设，不是固件验证过的 UTC：训练要求手机准确设时，并声明保守的参考时钟误差界。初始声明手机／量化界为 1 秒，再加实测传输、探针窗口与采样不确定度；实测清醒 HRT 使用保守 50 ppm 预算。误差界未知、客户端时钟跳变或单调时间不一致时，样本不合格；这不是绝对精度保证。

两个同源合格参考之间计算 `true_bridge = reference_utc_delta - measured_awake_hrt_delta`，再求 `candidate_ppm = (raw_bridge_delta - true_bridge) * 1000000 / true_bridge`。不能从已补偿墙钟误差或 SDK／私有估值差学习。初始软件门槛为区间为正且顺序有效、原始桥接暴露至少 6 小时、每次观测至多 30 天、保留状态连续有效、合并不确定度不超过暴露量的 100 ppm；发布系数前要求两个互不重叠的合格观测，其候选差异不超过 200 ppm 与合并不确定度两者中的较大值。这些是保守准入规则，不是残余 UTC 精度承诺。数据不足时继续累计至上个合格基线；已消费、拒绝或重复的观测不能重试为新证据。

冷／软件／欠压复位、损坏、换源或算术失败使学习连续性失效，不擦账号，也不删除最后一个有效持久系数。使用前检查源、版本、CRC 和界限。只保存合格的显著变化，保守 24 小时预算内至多一次自动写入尝试，失败也消耗预算，维护启动不提交 NVS。无记录时首次保存与已有记录冷启动预算的语义必须在测试中明确。

### 十五分钟正常维护与按键交还

在任何 BSP 初始化前检查完整唤醒原因掩码，不能只用可能优先返回 timer 而隐藏同时 GPIO 的单一原因。只有深睡复位、预期已武装定时器、有效且匹配的会话／可信 UTC，以及没有用户证据时才能静默维护。保留 SDK 默认 stub，不用实验测频／重睡 stub。只初始化必要 SDK／NVS／时钟资源，结算前段一次，重新直接测频，再武装 900 秒定时器及 GPIO0 低电平唤醒；该路径不初始化 I2C、ADC 按键组件、LVGL／显示、音频、Wi-Fi、BLE，不读温度、不提交 NVS；不新增常驻任务或无限历史。

### 评审后明确的边界约束

- 即使后续 1 ms 检查失败，设时返回成功也是不可逆的应用边界。将该段标为已消费／已应用但不确定，使学习连续性失效，记录故障并进入 UTC 不可信的完整启动；同次启动禁止第二次替换。只有返回失败且未改变墙钟的设时，才保留原活动段可重试；非深睡复位照常使保留状态失效。
- N 段恢复后，准备的 N+1 在入睡前只是暂存。取消／拒睡只丢弃 N+1 锚点、武装及暂存清醒区间闭合，保留 N 的已消费状态、已接受原始／修正累计量、小数状态及恢复 UTC。清醒区间从 N 的 HRT 采样点继续计至取消；以后启动／重武装不能恢复 N+1 或重新启用 N。暂存提交前保存 N 完成后的检查点；回滚后按当前 HRT 重新求清醒坐标，不能丢失或重算两次。
- 原始累计时间保留为整数微秒与 Q19 小数；修正 UTC 的 Q19 相位小数与比例除法余数及其分母分别保留。每段原始增量只加入累计坐标一次，新段不能重复加入历史累计小数。整数 UTC 设时只发布整数部分；相位余量跨消费／重武装保存并附着新锚点，不能作为历史修正再加一次。商／余数比例换算返回整数／Q19 输出，以及小于 `D = 1000000 + ppm` 的余数；中间乘积须适合检查过的 64 位运算。D 改变时先求 `r_new = floor(r_old * D_new / D_old)`，每次表示时间损失小于 `1/(D_new * 2^19)` 微秒并计入不确定度；不能用新 D 解释旧分子。显式成功校时有意重置相位小数，原始学习快照仍独立。参考算法测试覆盖分段不变性、换系数及取消回滚。
- 跨启动维护累计清醒坐标，不能相减不同启动的 HRT。每段桥接覆盖原始 tick 锚点至配对结束 tick；已知清醒区间覆盖该点 HRT 至下一锚点，包含浏览器探针两端的部分区间。每个参考 HRT 原子快照累计原始桥接量与已知清醒量，后者由本次启动的结束／基点加 HRT 推进计算；同一区间不能同时属于二者。同次启动晚处理的探针，从执行时清醒坐标扣除实测 HRT 年龄。手动设时终止学习连续性；合格浏览器设时在改变 UTC 前快照原坐标、只消费一次旧观测，并在配对点开始下一参考窗口。暴露不足时延长旧窗口，完整观测无效／拒绝时建立新基线，不复用失败区间；等价原始／清醒／参考轨迹不能仅因启动次数不同而学出不同系数。
- HTTP 探针缓存为四个数值条目，使用非零递增标识并绑定已有热点会话，热点重启使缓存失效。探针 UTC 为浏览器 GET 前后 UTC 的中点，与设备返回的 HRT 中点配对；执行目标为参考 UTC 加 `execution_hrt - probe_hrt`。客户端单调 RTT 须为正且不超过 2 秒，UTC 经过量与单调经过量的差不超过 100 ms，设备采样窗口不超过 1 ms。学习用的探针至执行总 HRT 年龄须在 0 至 5 秒内，包括浏览器停留和设备排队。误差预算包括声明的 1 秒时钟／量化界、半 RTT、半设备窗口与采样／清醒预算；执行 HRT 必须属于同一有效启动。有效提交被接受派发时即消费探针，即使之后入队失败或设时失败，重试也须新探针；重放、陈旧或不一致质量不能形成新学习观测。其他有效旧命令／显式同步仍可只校时不训练，但不能用无效 HRT 配对推进目标；所有学习效果以设时返回成功为条件。
- 公开缓存 ID 递增，但内部参考身份还包含热点随机数，跨会话／启动应视为不透明值。用独立 UTC 水位拒绝相同身份或非递增参考 UTC，不能按含随机数的 ID 数值判断新旧。基线、暴露不足、完整消费及有意重建均推进两个水位，格式无效、源不符或算术失败不推进；参考倒退须建立新连续性。只有已完成启动接续才可训练；失败仍可重试的桥接之后，接受显式参考只校时并丢弃不完整学习区间。每个完成桥接将保守 2000 微秒累加到当前基线不确定度，直到窗口消费／重建，不改变 UTC 目标。保留结算先按字节校验 CRC，再解码布尔值。
- 先将每组准入候选四舍五入为整数 ppm，恰好半值时向零取整，再按原始有效暴露时长加权两组一致的整数候选，并采用相同舍入规则发布。每次量化至多 0.5 ppm，系数算术的组合量化至多 1 ppm，独立于 100 ppm 的参考／结算准入界。24 小时 +1000.4 ppm、12 小时 +1000.8 ppm 的回归因此发布 1000 ppm，不是未量化比例加权后再舍入；这个界不是硬件精度承诺。系数须已合格且相对最后有效保存值至少变化 10 ppm，才属于持久化显著变化。所有系数自动保存，包括无记录时首次保存，都须距冷启动或上次写入尝试两者中较晚者，积累至少 24 小时有效内部计时。冷启动总是重新完整等待，因此丢失保留失败状态不能打开立即写入额度；失败尝试消耗下一完整预算，计时连续性缺失／损坏时禁止自动写入，直到重新建立完整区间。无记录只能在等待后首次保存合格系数；异常／不支持的已有记录仍禁止覆盖。不在维护时提交、不逐次同步写入，也不用本身会形成重启写循环的持久尝试标记。

从通过不确定度准入的窗口频偏做暴露时长加权，以加权中位数筛查异常，并沿用两个独立窗口的一致性下限：200 ppm 与合并不确定度两者中的较大值。频偏由保存的原始／参考增量重算，不能平均历史已舍入的发布系数。证据不足、冲突、陈旧或超出支持条件时保留现用系数，单条新记录不能发布替换。不能把相关参考误差除以记录数平方根而虚构置信度提升。启用自适应前，须由确定性回放／时间顺序留出验证固定估计阈值、老化与发布规则，并明确版本化；不能为了拟合这两次供电试验随意增加模型参数。

影子验证后另设启用检查点：要求独立证据一致，且在更新的留出窗口上，相对不变标量基准的改善能够在不确定度内成立。候选不超出现有准入界，只在段边界向后生效，不放松安全倒计时，不追改已过去 UTC。初期保留整数活动 ppm 与现有经过测试的比例运算；小数活动系数需另行评审定点／溢出／余数契约并执行参考算法测试，多显示小数本身不能证明物理精度。

复用正常运行期温度和 `bsp_battery_mv()` 采样，记录有效性、年龄和覆盖范围。CW2017 报告电池端电压，不是已证实的 VBUS、充电状态或振荡器电源电压；充电 IC 和供电遥测仍未确认。不能把可能写 profile 并等待 SOC 的完整电池初始化塞进定时维护；本增量不增加维护 I2C／传感器操作。不能由清醒端点拟合睡眠温度轨迹，留出数据证明收益前不启用温度／电压补偿。

### 已授权的实施调整：独立历史分区
